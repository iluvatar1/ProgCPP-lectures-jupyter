Multiplicative (* / %) outranks additive (+ -), which is why 2 + 3 * 4 is 14, not 20. Both comparison rows outrank both logical rows, which is why a < b && c > d parses as (a < b) && (c > d) with no extra parentheses needed.

Pre-increment vs. post-increment

++i increments i first, then produces the new value. i++ produces the current value first, then increments i as a side effect. They only differ when you use the result of the expression — i ends up the same either way.

The chaining pitfall

Unlike math notation, a < b < c in C++ does not check whether b is between a and c. Comparisons are left-associative, so it evaluates as (a < b) < c: the true/false result of the first comparison (as 1 or 0) gets compared to c.

What C++ actually does: (a < b) < c
What you probably meant: (a < b) && (b < c)
Comparing floating-point values with == is its own hazard: rounding means two mathematically equal computations can end up as slightly different bit patterns. Prefer checking that the difference is within a small tolerance.

Bitwise AND / OR / XOR / NOT — the same names, working on bits

Don't confuse these with &&, ||, ! above: &, |, ^ and ~ don't treat their operand as one true/false value. They line up every bit of the operands and combine each column independently — no short-circuiting, and the result is a number, not a bool.
